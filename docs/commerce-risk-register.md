# Commerce — risk register (Phase 0)

Status column updated 2026-10-09 after Phases 0.5 and 1 (see `commerce-rollout.md`).

Severity: **High** = money can be lost/mis-stated or abused today · **Med** = correctness/ops gap that the
Commerce Engine must solve or it will inherit it · **Low** = hygiene. "Exists today" means the issue is in the
current production code path, independent of the new work. All evidence is from reading code at `544e663`;
items marked *(verify)* should be reproduced in the isolated QA DB before being fixed.

## Areas that must remain untouched by the Commerce Engine work

- Circle code (`circles.ts`, `circleHelpers.ts`, `circle_*` tables) — no commerce surface; frozen.
- The five participation tables' existing columns and state values — additive columns only, never repurpose.
- `refundPaidOnce` / `issueStripeRefund` exactly-once semantics (HC-QA-051/091) — extend, don't rewrite.
- `settlePending` late-payment handling (HC-QA-041) — reuse as-is; the order layer wraps it.
- `stripeWebhookPolicy.ts` fail-safe signature rules (HC-QA-048) — unchanged.
- Identity middleware order (`attachUser → attachGuestEmail → attachResident`) and `orgVendorIds`.
- `testProfile.ts` / `testIsolated.ts` isolation guards (HC-QA-092).
